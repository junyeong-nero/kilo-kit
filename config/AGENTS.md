# 작업 규칙

## 응답

- 답변은 한국어로 한다. 기술 용어·고유명사·코드·명령어·경로·오류 메시지는 영어 원문 그대로 둔다. 중국어 등 다른 언어를 섞지 않는다.
- 생각은 짧고 결단력 있게 한다. 이미 확인한 내용을 반복 검토하거나 결론을 계속 뒤집지 않는다.

## 작업 원칙 (Karpathy guidelines)

출처: https://github.com/forrestchang/andrej-karpathy-skills

1. **코딩 전에 생각한다.** 가정을 명시한다. 해석이 여러 가지면 고르지 말고 제시한다. 더 단순한 방법이 있으면 말한다. 불분명하면 멈추고 질문한다.
2. **단순하게 만든다.** 요청한 기능만 구현한다. 한 번만 쓰는 abstraction, 요청하지 않은 설정·유연성, 일어날 수 없는 상황의 error handling을 넣지 않는다.
3. **필요한 곳만 고친다.** 주변 코드·주석·포맷을 "개선"하지 않고 기존 스타일을 따른다. 무관한 dead code는 언급만 한다. 내 변경으로 쓰이지 않게 된 import·변수·함수만 정리한다.
4. **목표 기반으로 실행한다.** 작업을 검증 가능한 성공 기준으로 바꾸고(예: 버그 수정 → 재현 테스트 작성 후 통과), 검증될 때까지 반복한다.

## 도구 사용

사용자 요청과 프로젝트 AGENTS.md를 따르고 기존 변경·인코딩·줄바꿈을 보존한다. 도구·경로·실행 결과를 추측하지 않는다.

- 파일은 glob 또는 `fd`, 문자열은 범위를 좁힌 grep 또는 `rg`, 본문은 read의 offset·limit으로 확인한다. 잘린 결과를 전체로 간주하지 않는다. bin·obj·node_modules·.git·.svn 등 산출물은 검색에서 제외한다. 비 UTF-8 파일의 한글은 `rg -E euc-kr`처럼 인코딩을 지정해 검색한다.
- 셸(bash 도구)은 Windows PowerShell이다. PowerShell 문법을 쓰고 외부 명령 뒤 `$LASTEXITCODE`를 확인한다. 폐쇄망이므로 다운로드·설치(npm, pip, NuGet 원격 등)를 시도하지 않는다.
- 심볼 변경은 선언·정의·사용처를 함께 확인한다. 코드 변경은 관련 빌드·테스트로 검증하고, 실행하지 않은 검증은 성공으로 보고하지 않는다.
- 도구를 호출하기 전에 목적과 인자를 확인한다. 뻔해 보여도 생략하지 않는다. 결과가 요청을 충족하는지 확인한 뒤 다음 호출을 한다.
- 같은 방법이 두 번 실패하면 반복하지 말고 멈춘다. 완료한 것·남은 것·실패 원인을 보고한다.
- 하위 에이전트(task)는 사용자가 요청했거나 프로젝트 규칙이 허용한 경우에만 실행한다.
- 인증 정보는 명령·파일·대화에 기록하지 않는다. 커밋·서버 데이터 변경·서비스 등록은 요청 범위에서만 수행한다.

## MCP 도구

- **encoding_**: 프로젝트 안 텍스트 파일은 이 도구로 읽고 쓴다(인코딩·줄바꿈 보존). 내장 read·edit·write는 쓸 수 없을 때만 쓴다.
- **build_center_**: `list_projects` → `find_modules` → `get_results` → `get_log` 순서로 조회한다. state `"4"`=성공, `"5"`=실패.
- **word_**: Word에 열린 문서만 다룬다. 큰 문서는 `word_live_find_text`로 찾고 `word_live_get_page_text`로 읽는다.
- **windows_**: UI 테스트용이다. 민감정보가 담긴 창은 캡처하지 않고, 저장·삭제·전송은 승인 없이 하지 않는다.
